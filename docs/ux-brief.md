## Platforms and constraints

- macOS and Linux — supported with bash 3.2+; Windows only through WSL (001 non-functional requirements).

- Claude Code — installed as a plugin, with namespaced `/sdd:<phase>` commands and updates; opencode, and Claude Code without the plugin, get the install script, which copies into a shared flat directory with `sdd-`-prefixed commands (001 plan, technical decisions).

## Content rules

- Client-facing documents are written entirely, headings included, in one language, the constitution's content language (002 FR-30).
- The PRD expresses each requirement as a plain sentence naming who benefits and what they get, without EARS keywords, `FR-` identifiers, or technical identifiers (002 FR-29).
- Client-facing documents omit internal risks, verification strategy, open questions, and unresolved `[NEEDS CLARIFICATION]` items; the scope change log omits each Reason (002 FR-27).
- Every generated document states the artifacts it was derived from, the generation date, and that the specs, plans, and constitution prevail on conflict (002 FR-25).
- A generated spec has its FRs in EARS notation and an "Out of scope" section (001 FR-10); each task carries a verifiable "Done when:" line (001 FR-14).
- A scope change entry is titled `CHG-n — YYYY-MM-DD — <title>` with the fields Type (`add`, `modify`, or `remove`), FRs, and Reason (002 FR-11).
- A skipped schema update is recorded with the exact text "schema: skipped, no schema source found" (002 FR-6).
- A section with no source in the app flow or UX brief is written as `TODO: provide <what>`, never invented (003 FR-7, FR-11).
- The app flow and UX brief keep the template's English headings, the notes heading, and the literal `TODO: provide` marker as fixed tokens, with the body in the content language; the delivery package is written entirely in the content language and has no version field, being titled by project (003 non-functional requirements).
- The delivery package writes requirements as plain sentences without EARS or `FR-` identifiers, omits risks, verification strategy, open questions, and change Reasons, and keeps untested situations out of its known limits (003 FR-16).
- A feature without a `## Known limits` heading gets one line in the delivery package saying no limits are recorded (003 FR-15).
